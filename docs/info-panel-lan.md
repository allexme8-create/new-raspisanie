# Как открыть `info_panel_1.html` по HTTP в локальной сети (Windows 10)

## Почему просто открыть файл недостаточно

`info_panel_1.html` из НИКА-Люкс открывать двойным щелчком (`file:///C:/...`)
нельзя: панель подгружает `schedule_panel.js` / `nika_data_*.js`, работает с
`iframe` и шрифтами из `images/` — при `file://` браузер режет такие запросы, и
страница либо пустая, либо «Не удается отобразить расписание». Нужен `http://`.

`web.config` в твоей папке — для **IIS** (там `defaultDocument` =
`info_panel_1.html`), он пригодится, если сервер будет постоянным (пункт 4).

---

## 1. Быстрее всего: готовый скрипт из репозитория (рекомендую)

В папке `tools/` лежат `serve_lan.py` и `serve.bat`.

1. Скопируй `serve_lan.py` и `serve.bat` в папку с расписанием
   (рядом с `info_panel_1.html`, `schedule_panel.js`, `nika_data_*.js`).
2. Двойной щелчок по **`serve.bat`**.
3. Откроется консоль и браузер: `http://localhost:8000/info_panel_1.html`.
4. В консоли будет напечатан адрес для других устройств, например:
   `http://192.168.1.50:8000/info_panel_1.html` — его и вводи на телевизоре /
   другом ПК / планшете.

Окно консоли закрывать нельзя — это и есть сервер.

Если Python нет: `winget install -e --id Python.Python.3.12` в PowerShell
(после установки — заново запустить `serve.bat`).

Тот же запуск вручную:

```cmd
cd /d C:\raspisanie
python serve_lan.py . -p 8000
```

Скрипт: слушает `0.0.0.0` (все интерфейсы), отдаёт `info_panel_1.html` как
страницу по умолчанию, ставит правильные MIME-типы для `.js/.css/.woff`,
отключает кеш (панель не будет показывать вчерашнее расписание) и печатает
все IP-адреса ПК.

---

## 2. Вариант без файлов: одна команда

```cmd
cd /d C:\raspisanie
python -m http.server 8000 --bind 0.0.0.0
```

Открывать: `http://localhost:8000/info_panel_1.html` (не `/` — встроенный
сервер не знает про `info_panel_1.html` как индексный файл).

Без Python — через Node.js:

```cmd
npx --yes http-server . -p 8000 -c-1 -o /info_panel_1.html
```

---

## 3. Обязательный шаг: разрешить порт в брандмауэре

Первый запуск обычно вызывает окошко «Разрешить доступ» — отметить **«Частные
сети»** и «Разрешить доступ». Если окошко не появилось или сеть помечена как
«Общедоступная», выполни PowerShell **от администратора**:

```powershell
New-NetFirewallRule -DisplayName "Raspisanie HTTP 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Private,Domain
```

Проверить, что сеть «Частная»: Параметры → Сеть и Интернет → Wi-Fi/ Ethernet →
профиль подключения. На «Общедоступной» Windows блокирует входящие.

Узнать IP ПК: `ipconfig` → «IPv4-адрес» (например `192.168.1.50`).
С другого устройства: `http://192.168.1.50:8000/info_panel_1.html`.

## 4. Постоянный вариант: IIS (использует твой `web.config`)

Если панель должна работать всегда после перезагрузки:

1. PowerShell от администратора:
   ```powershell
   Enable-WindowsOptionalFeature -Online -FeatureName IIS-WebServerRole,IIS-WebServer,IIS-StaticContent,IIS-DefaultDocument -All
   ```
2. Скопировать папку расписания, например в `C:\inetpub\wwwroot\raspisanie`
   (вместе с `web.config` — он и сделает `info_panel_1.html` страницей по
   умолчанию).
3. Открыть `http://localhost/raspisanie/` или, чтобы совсем коротко,
   `inetmgr` → «Сайты» → «Default Web Site» → «Добавить веб-сайт»… либо
   перенастроить корень на `C:\raspisanie`.
4. Брандмауэр: разрешить порт 80 (или тот, что указан в привязке сайта).
5. Служба `W3SVC` стартует вместе с Windows — ничего запускать не нужно.

Плюсы: нет окна консоли, работает как служба, корректно отдаёт `web.config`.
Минус: возни больше, и правка файлов в `wwwroot` требует прав администратора.

## 5. Автозапуск «как сервис» без IIS

Если хочется именно Python-сервер, но чтобы стартовал сам:

1. Создай `C:\raspisanie\start-server.cmd`:
   ```cmd
   @echo off
   cd /d C:\raspisanie
   C:\Users\<ты>\AppData\Local\Programs\Python\Python312\python.exe serve_lan.py . -p 8000
   ```
2. `Win+R` → `shell:startup` → положи туда ярлык на этот `.cmd`.
3. Чтобы не висело окно консоли — запускать через Планировщик заданий
   («При входе в систему», «Выполнять вне зависимости от входа пользователя»,
   галка «Скрыть»).

## 6. Проверка и типовые проблемы

| Симптом | Что делать |
|---|---|
| На этом ПК открывается, на других — нет | брандмауэр (п. 3) или сеть «Общедоступная»; проверь, что сервер запущен с `--bind 0.0.0.0` |
| `Address already in use` / «порт занят» | `netstat -ano \| findstr :8000` → `taskkill /PID <pid> /F`, либо порт `-p 8080` |
| Страница пустая / «Не удается отобразить расписание» | открыт `file://` вместо `http://`; либо не хватает `.js`-файлов в папке (должны лежать рядом: `schedule_panel.js`, `nika_data_*.js`) |
| Расписание старое | сервер с `Cache-Control: no-store` (наш скрипт уже так делает), либо `Ctrl+F5` в браузере |
| Панель не обновляется сама | в `nika_data_*.js` задан `initial_schedule_id`; автообновление работает только когда НИКА отдаёт `/check` — в статической папке расписание просто перезаливается новым файлом `nika_data_*.js` |
| Шрифты/иконки не грузятся | следи, чтобы папка `images/` (RomanaScript.woff/.ttf/.svg и прочее) была скопирована целиком |
| Кириллица кракозябрами в консоли | это только консоль; на странице кодировка задана в самом HTML (`charset=utf-8`) |

Проверить доступность из сети на самом ПК:
`http://192.168.1.50:8000/info_panel_1.html` (не `localhost` — так проверяется
именно сетевой путь).

---

## TL;DR

```cmd
cd /d C:\raspisanie
python serve_lan.py . -p 8000
```
→ на этом ПК `http://localhost:8000/`, в локальной сети
`http://<IP>:8000/` → разрешить порт 8000 в брандмауэре (профиль «Частная»).
