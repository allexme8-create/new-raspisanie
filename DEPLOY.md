# 🚀 Публикация расписания на бесплатном хостинге

## Рекомендуемый вариант: PythonAnywhere (бесплатный тариф)

Для этого проекта подготовлен WSGI-адаптер `backend/wsgi.py`. Размещение требует один раз выполнить команды в консоли и указать путь к приложению в настройках сайта. Учетную запись хостинга и действия в её панели должен выполнить владелец.

### 1. Создайте бесплатный сайт

1. Зарегистрируйтесь на [PythonAnywhere](https://www.pythonanywhere.com/).
2. Откройте вкладку **Web** → **Add a new web app**.
3. Выберите **Manual configuration** и версию Python **3.11**.
4. Запишите имя пользователя PythonAnywhere: оно будет частью адреса `https://ИМЯ.pythonanywhere.com`.

### 2. Скачайте проект и установите зависимости

Во вкладке **Consoles** откройте **Bash** и выполните:

```bash
git clone https://github.com/allexme8-create/new-raspisanie.git
cd new-raspisanie
python3.11 -m venv .venv
. .venv/bin/activate
pip install -r backend/requirements.txt
```

Если `git clone` не проходит из-за ограничений доступа, скачайте ZIP репозитория с GitHub, загрузите его через вкладку **Files**, распакуйте в домашнюю папку, затем продолжите с `cd new-raspisanie`.

### 3. Подключите WSGI-приложение

Во вкладке **Web**:

1. В поле **Source code** укажите `/home/ИМЯ/new-raspisanie`.
2. В поле **Virtualenv** укажите `/home/ИМЯ/new-raspisanie/.venv`.
3. Откройте ссылку на WSGI configuration file и замените его содержимое следующим кодом. Замените `ИМЯ` на имя пользователя, а пароль — на свой длинный секретный пароль (не используйте пример):

```python
import os
import sys

project = "/home/ИМЯ/new-raspisanie"
if project not in sys.path:
    sys.path.insert(0, project)

os.environ["ADMIN_PASSWORD"] = "ЗАМЕНИТЕ_НА_СЕКРЕТНЫЙ_ПАРОЛЬ"
# На PythonAnywhere файлы хранятся на постоянном диске,
# поэтому BACKUP_GH_TOKEN для резервной копии не требуется.

from backend.wsgi import application
```

В приложении выберите Python 3.11 и для Web app, и при создании `.venv` — версии должны совпадать.

### 4. Перезапустите и проверьте сайт

Нажмите **Reload** на вкладке **Web**. Откройте `https://ИМЯ.pythonanywhere.com`, затем `https://ИМЯ.pythonanywhere.com/admin`. Войдите с паролем, заданным в WSGI-файле, и загрузите оба файла расписания.

Проверки: `/healthz` должен отвечать `{"ok":true}`, а `/api/status` покажет, загружено ли расписание. Используйте загрузку файлов с устройства: на бесплатном аккаунте исходящие запросы к внешним сайтам могут быть ограничены, поэтому загрузка с Яндекс.Диска может не сработать.

> **Важно:** не публикуйте пароль администратора. Если сайт показывает ошибку, откройте вкладку **Web** → **Log files** и проверьте error log. После изменения кода или WSGI-настроек нажимайте **Reload**.

## Альтернатива: Hugging Face Spaces

Hugging Face Spaces тоже поддержан (инструкция ниже), но у бесплатных аккаунтов может сработать ограничение CPU-квоты. В таком случае Space не запускается даже при корректной сборке.

Полностью без командной строки, через GitHub Actions (`.github/workflows/deploy-hf.yml`):

1. Создайте Space: https://huggingface.co/new-space → имя `raspisanie` (маленькими!), SDK **Docker** → Blank, Public.
2. Создайте HF-токен: https://huggingface.co/settings/tokens → Create new token → **Write**.
3. Добавьте секреты в GitHub (https://github.com/allexme8-create/new-raspisanie/settings/secrets/actions): `HF_USERNAME` = ваш логин HF, `HF_TOKEN` = токен. Если имя Space отличается от `raspisanie`, добавьте `HF_SPACE_NAME` с точным именем.
4. GitHub → **Actions** → **🚀 Deploy to Hugging Face Spaces** → **Run workflow**.
5. В Space откройте **Settings** → **Variables and secrets** и задайте `ADMIN_PASSWORD`, `BACKUP_GH_TOKEN`, `BACKUP_GH_REPO=allexme8-create/new-raspisanie`.
6. Адрес: `https://ЛОГИН-raspisanie.hf.space`.

Если видите `You've reached your base CPU quota`, повторные перезапуски могут не помочь: это ограничение аккаунта/квоты HF, а не ошибка приложения.

## Альтернатива: Render

Проект содержит `render.yaml`, однако Render может быть недоступен из вашей сети. Если он открывается:

1. Откройте https://render.com и войдите через GitHub.
2. Нажмите [Deploy to Render](https://render.com/deploy?repo=https://github.com/allexme8-create/new-raspisanie) и примените Blueprint из `render.yaml`.
3. В **Environment** задайте `ADMIN_PASSWORD` и, если хотите резервную копию в GitHub, `BACKUP_GH_TOKEN`.
4. После статуса **Live** используйте адрес сервиса Render и страницу `/admin`.

Бесплатный Render может усыплять сервис после периода простоя; первый запрос после сна занимает дольше.

## Запуск на собственном сервере

```bash
git clone https://github.com/allexme8-create/new-raspisanie.git
cd new-raspisanie
docker build -t raspisanie .
docker run -d -p 8000:8000 \
  -e PORT=8000 -e ADMIN_PASSWORD="секрет" \
  -e BACKUP_GH_TOKEN=... -e BACKUP_GH_REPO=allexme8-create/new-raspisanie \
  -v raspisanie_data:/app/backend/data \
  --restart unless-stopped raspisanie
```

## Проверка после деплоя

1. Откройте `/api/status` — пока расписание не загружено администратором: `{"ready":false,...}`.
2. Откройте `/admin`, войдите и загрузите оба файла расписания. Для проверки можно взять файлы из `samples/`.
3. Главная страница должна показать расписание; в админке отображается статус резервной копии, если она настроена.

## Учётные записи руководства и задачи

В `/admin` укажите e-mail как логин и выберите роль директора, заместителя или учителя. При создании можно указать ФИО и должность, например «учитель начальных классов»; сотрудник также может изменить ФИО и должность в своём профиле. Должность отображается рядом с ФИО, но не меняет роль и права доступа. Если должность не задана, используется название роли. Сервис создаёт случайный пароль и показывает его администратору. Передайте логин и пароль пользователю безопасным способом: письма сервис не отправляет. Вход директора — `/Director`, заместителя — `/associate`, учителя — `/teacher`. При первом входе пользователь меняет пароль. Если пароль забыт, администратор может показать текущий или создать новый; обновление пароля закрывает активные сеансы и снова требует его сменить при входе.

Администратор может видеть действующие пароли, включая изменённые пользователями. Это повышает последствия компрометации админки: используйте HTTPS, надёжный `ADMIN_PASSWORD` и независимый `ADMIN_TOKEN_SECRET`, ограничьте доступ к админке и серверу. Проверка входа использует scrypt-хеш, а копия пароля хранится в SQLite в зашифрованном виде. Ключ автоматически создаётся в `backend/data/staff.key` с правами доступа только для владельца и хранится рядом с базой; шифрование не защитит от злоумышленника, получившего доступ и к базе, и к ключу или к аккаунту администратора. Не отправляйте пароли и ключи в чат и не добавляйте их в Git.

Храните `backend/data` на постоянном диске. База `staff.sqlite3` и ключ `staff.key` не входят в GitHub-бэкап расписания; настройте защищённые резервные копии обоих файлов (ключ храните отдельно от базы) и проверяйте восстановление. На эфемерном диске без резервной копии данные будут потеряны. Если ключ утрачен, существующие пароли нельзя показать или обновить до восстановления ключа. Пароли старых пользователей, сохранённые только как хеши до введения этой функции, невозможно показать: администратор должен обновить их пароли, после чего новая версия будет доступна для просмотра.

Удаление пользователя блокирует вход, закрывает сеансы и удаляет учётные данные; история задач сохраняется с пометкой «Удалённый пользователь». Директор назначает задачи заместителям и учителям, заместитель — учителям. Директор и заместители создают проекты; директор видит задачи всех проектов, заместитель — задачи своих проектов, созданные им и назначенные ему задачи. Учитель видит только назначенные ему задачи и связанные проекты. Участники чужих проектов видят только свои задачи, а не общий прогресс. Инициатор невыполненной задачи может пригласить в неё любого активного сотрудника: соисполнитель видит задачу, её комментарии и историю событий и может комментировать, но не получает доступа к остальным задачам проекта. Инициатор и основной исполнитель получают уведомления в личном кабинете о новых чужих комментариях; инициатор также получает уведомление о выполнении задачи; инициатор может вернуть выполненную задачу на доработку с обязательным комментарием и новым сроком, после чего исполнитель получит уведомление; уведомление считается прочитанным после открытия её истории. Проверка новых событий происходит примерно раз в 30 секунд при открытом кабинете; письма и push-уведомления не отправляются. История изменений состояния записывается начиная с внедрения этой функции; ранние изменения восстановить нельзя. Каждый, у кого есть доступ к задаче, может читать и добавлять комментарии к ней; только исполнитель может отметить частичное выполнение и указать или изменить причину невыполнения. После полной отметки частичная отметка снимается, а указанная ранее причина остаётся в истории задачи. Исполнитель может снять ошибочную отметку выполнения до окончательного подтверждения; инициатор получает уведомление; ошибочная отметка и её снятие не отображаются в истории задачи (события остаются в серверном журнале). Инициатор может подтвердить выполненную исполнителем задачу как «выполнено полностью»; после этого вернуть её на доработку нельзя. Инициатор может убрать свою задачу из личного списка в любой момент, исполнитель и соисполнители — только после окончательного подтверждения. Удаление персональное и не удаляет историю или задачу у других; её можно найти и вернуть через «Показать удалённые мной». Создатель проекта может подтвердить полное выполнение проекта после подтверждения всех его задач; после этого добавление задач закрыто. В проектах показано выполнение задач и участие исполнителей; отметка выполнения доступна только назначенному исполнителю; вернуть задачу на доработку может только её инициатор, при этом история выполнения сохраняется. Срок вводится в часовом поясе устройства автора задачи, статус рассчитывается по серверному времени. В разделе «Статистика сроков» директор и заместитель выбирают основного исполнителя по ФИО и видят число поставленных ими задач, выполненных в срок и просроченных по действующему сроку; учитываются проектные и удалённые из личного списка задачи. В просроченные входят незавершённые после срока и завершённые позднее срока. Завершение считается по отметке исполнителя, а возвращённая на доработку задача — по новому сроку; отдельного учёта согласований вне системы нет. Данные и тексты задач могут содержать персональную информацию.

Почтовые настройки и OAuth-подключения из предыдущих версий больше не используются; локальные токены удаляются при обновлении базы. Чтобы отозвать доступ на стороне почтового провайдера, удалите разрешение приложения в настройках почтового аккаунта. Сброс пароля по e-mail больше не поддерживается.

### Дежурство

В кабинетах учителей и заместителей доступна общая карта текущей четверти. По умолчанию четверти: 1 сентября — 31 октября, 1 ноября — 31 декабря, 10 января — 31 марта, 1 апреля — 31 мая. Любой заместитель может изменить даты четырёх четвертей для выбранного учебного года в разделе «Даты учебных четвертей»: периоды должны идти по порядку, не пересекаться и находиться между 1 августа и 31 июля следующего года. Настройки общие и сохраняются отдельно для каждого учебного года; для ненастроенных лет действуют даты по умолчанию. Воскресенья исключены из карты и для них нельзя создавать новые назначения. Ранее существовавшие записи, в том числе на воскресенья или даты за пределами изменённых четвертей, не удаляются, но не показываются в карте; если вернуть даты четверти, прежние записи на допустимые дни снова появятся. Во время каникул показывается следующая четверть; запись открывается с её начала. Учитель выбирает свободное место в одной из двух смен и указывает класс, заместитель — свободное место дежурного администратора либо место учителя, выбрав зарегистрированного учителя и указав его класс. Назначить можно активного учителя с заполненным ФИО; назначенный учитель видит запись как свою и может её отменить. Заместитель может отменить только собственное дежурство администратора. На дату предусмотрены один администратор и по одному учителю в каждой смене. Можно отменить собственную предстоящую запись.

Заместители могут задать общий недельный шаблон дежурных администраторов на понедельник — пятницу. Сохранённый шаблон действует начиная с текущей даты и повторяется в последующих учебных четвертях до изменения; прошедшие даты не пересчитываются. Субботы, воскресенья и периоды вне заданных четвертей шаблон не заполняет; отдельные праздничные дни автоматически не исключаются. Уже существующие записи на конкретную дату имеют приоритет. Кнопка «Изменить на эту дату» позволяет назначить другого заместителя или оставить дату свободной, не меняя шаблон; «Вернуть обычное назначение» снимает эту замену и восстанавливает прежнюю разовую запись либо шаблон. Записи и шаблоны общие для всех заместителей. Удалённые сотрудники автоматически не назначаются.

Календарный день для дежурств определяется часовым поясом школы, по умолчанию `Asia/Krasnoyarsk`. Для другой школы задайте переменную окружения `SCHOOL_TIMEZONE` в формате IANA и перезапустите сервер. Текущая смена на странице расписания определяется по расписанию звонков школы; при отсутствии звонков или вне интервалов смен она не выделяется. **ФИО, должность и класс сегодняшних дежурных видны всем посетителям при открытии расписания выбранного класса или учителя.** Записи хранятся в `staff.sqlite3` и требуют резервирования вместе с остальными данными персонала.

### Справочники и классное руководство

Классы из загруженного расписания автоматически добавляются в справочник конструктора при первом запуске новой версии и при последующих загрузках файлов. В конструкторе также доступна кнопка «Добавить классы из расписания»; повторный импорт не создаёт дубликатов и не заменяет существующие данные черновика. Классы и предметы создаются в разделе «Конструктор расписания → Справочники» в админке. Сохранённые классы из черновика сразу доступны для классного руководства и дежурства, публиковать расписание для этого не требуется. При создании учителя можно выбрать классное руководство; его также можно назначить, изменить или снять у существующего учителя через «Редактировать пользователя» в списке пользователей. Там же можно изменить ФИО, e-mail и должность; роль не изменяется, пароль управляется отдельными кнопками. При изменении e-mail прежние сеансы остаются действительными. Указывайте класс для роли учителя; для других ролей это поле недоступно.

При самостоятельной записи учителя или назначении заместителем автоматически используется его классное руководство. Если оно не задано, класс выбирается из справочника; пока справочник пуст, сохраняется прежний ручной ввод. Назначение запоминает класс на момент записи, поэтому изменение классного руководства не переписывает уже созданные дежурства. Класс с действующей привязкой к учителю нельзя удалить из черновика, пока администратор не изменит или не снимет привязку. Несколько учителей могут быть привязаны к одному классу.

Черновик конструктора хранится в `state.json`, а привязки и дежурства — в `staff.sqlite3`; резервируйте и восстанавливайте их согласованно. Приложение использует общую блокировку внутри процесса для изменения справочника и привязок; как и для остальных операций с черновиком в `state.json`, используйте один процесс приложения на общий каталог данных.
